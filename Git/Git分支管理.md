# 项目GIT分支管理方案

### 项目分支
* master(主分支，，唯一分支，受保护)
* release(预发布分支，唯一分支)
* hotfix(紧急修复分支，唯一分支)
* develop-(版本号)(开发分支)
* feature-(版本号)(特性分支)
* patch-(版本号)(补丁分支)
* test(测试分支)
* test-merge(测试合并分支)

### 分支管理

#### master分支(生产环境主分支)
- 只能从 release 和 hotfix 分支进行合并
- 根据项目要求是否设置审查通过后允许合并

#### release分支(预发布分支)
- 常规版本上线发布分支
- 只能从 develop 和 feature 关联分支进行合并（合并前需先从master分支进行合并）

#### hotfix分支(紧急修复分支)
- 紧急修复生产环境中的问题发布分支
- 每次 release 分支发布后需主动将master分支合并到hotfix分支
- 使用方法
    - 直接在常规版本分支进行代码开发，测试完成后通过 cherry-pick 的方式转移到hotfix分支发布代码
    - 基于 hotfix 分支新建 patch-临时分支 进行代码开发，测试完成后合并到hotfix分支发布代码，该分支发布完后需主动合并到常规分支代码

#### develop(开发分支)
- 项目常规版本开发分支
- 版本号命名规则为：常规版本(develop-月日-相关标识)

#### feature(特性分支)
- 项目开发特性功能专用分支
- 版本号命名规则为：特性分支(feature-月日-相关标识)

#### patch(补丁分支)
- 项目解决非紧急bug的分支
- 版本号命名规则为：特性分支(patch-月日-相关标识)

#### test分支(测试分支)
- 项目测试环境分支，测试专用分支，只能从 test-merge 分支进行合并

#### test-merge分支(测试合并分支)
- 项目测试合并分支，用于进行复杂合并测试的分支，所有需要上测试的代码分支需先合并到该分支

## CI/CD 流程
- 当 develop 和 feature 关联分支有推送操作是，自动合并到 test-merge 分支，如果有冲突则把冲突相关问题文件信息推送到webhook
- release 分支有推送操作有自动合并到 hotfix 分支
- 定时清理 develop 和 feature 关联分支大于3个月时间的分支
